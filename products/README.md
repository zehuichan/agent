# 产品文档

本目录每篇对应一个产品，按 `../README.md` 的五类骨架判型、填目录、定硬规则。写到能上线运营的程度：身份权限、合规、版本、审计、可观测、成本、值班都在范围内（见「运营基线」）。

每篇固定几节：产品与判型、不能照搬的原型做法、运营要求、技术栈、目录、层 → 目录、硬规则、完成线、第一条 eval、换型信号。

## 不能照搬的原型做法（共性）

五篇里反复出现的同一批问题：

| 原型做法 | 问题 | 替代 |
| -------- | ---- | ---- |
| 单用户、无登录、无角色 | 谁都能看原文、导数据、改知识 | 企微 / SSO 登录；角色与数据范围；访问日志 |
| SQLite、本地盘、本地文件向量库 | 单写者、单机、无备份、无生命周期 | PostgreSQL（+pgvector）、对象存储、保留期 job、备份与恢复演练 |
| 供应商 key 写 `.env` / `config.yaml`，业务原文直发模型 | 无计量、无降级、数据出企业边界说不清 | 只经能力平台网关（`ai-platform.md`）；数据分级决定供应商；脱敏在前 |
| API 与 runner 同进程、SSE 由 runner 直推 | 重启丢任务、不能扩 worker、前端耦合执行 | 任务表 + 租约 + 独立 worker；进度只追加 entries，前端拉 |
| 浏览器算力（FFmpeg.wasm） | 用户必须开着页面 | 服务端 worker |
| Mock LLM「换 Provider 就行」 | 真模型有超时、限流、幻觉；Mock 跑不出来 | 录制真模型响应做回归；超时 / 降级 / 备用模型是产品的一部分 |
| 「一键清洗」「通过并入库」立刻生效 | 无版本、无回归、错了不能回滚 | 草稿 → 审核 → 回归通过 → 发布版本；回滚 = 切版本 |
| 图 / 流程写在代码里 | 改流程要发版 | 图是版本化数据；runner 只加载已发布版本 |
| 没有 eval 集 | 只能靠人看 | 每产品一个第一条 eval + 回归集，当发布门禁 |
| 没有合规 | 原型不需要 | 个保法（告知同意、最小必要、删除权、委托处理）、AI 生成内容标识、平台规则、录音告知 |

## 产品之间怎么接

每条箭头都是一次**版本发布**，不是表间直读：

```text
企微会话存档 ──▶ 销售对话数据平台 ──发布知识库版本──▶ 能力平台·检索集合 ──▶ AI 客服（文本 / 语音）
                        │                                                  ▲
                        ├──发布数据集版本──▶ 微调（外部流程）              │
                        └──异议摘要──▶ 素材库 ◀──切片 / 标题── 直播自动切片
                                          │
                                          ▼
                                   内容运营工作流 ──官方接口 / 人工──▶ 平台 ──数据回收──▶ 素材库
交付知识（归档 → 审核 → 版本）──▶ 能力平台·检索集合 ──▶ 履约管家 ◀──只读── 订单系统
所有产品的模型 / embedding / prompt 调用 ──▶ 能力平台网关（计量、预算、降级、审计、分级放行）
```

跨产品只共享三样东西：能力平台、素材库、身份（企微 / 客户账号）。不共享数据库、不共享进程、不共享 session。

## 运营基线（P0 必备）

各篇的「运营要求」一节都按这张表填，不重复解释：

| 项 | 最低要求 |
| -- | -------- |
| 身份与权限 | 登录、角色、数据范围（销售只看自己、租户隔离）；tools 身份透传，不用上帝账号 |
| 合规 | 合法性基础写下来（同意 / 告知）；最小必要；删除权级联；第三方处理有协议；AI 内容标识；录音告知 |
| 数据分区与分级 | 原文区 / 脱敏区 / 已发布区；分级决定能送哪家供应商、能不能留日志正文 |
| 版本 | 知识库、数据集、prompt、流程图、检索集合都有版本；发布要过 eval；回滚 = 切版本 |
| 审计 | 谁看了 / 改了 / 导出了 / 发布了；审计日志不可改 |
| 可观测 | 每产品一张看板：吞吐、失败率、积压、时延、成本 / 天 |
| 成本 | 预算按项目 / 租户；超限告警、限流或降级，策略可配 |
| 可靠性 | 模型超时 / 供应商故障有降级路径，不静默失败；任务类产品有租约、重试、死信 |
| 数据生命周期 | 保留期配置化，清理 job 是产品的一部分；备份与恢复演练 |
| 值班 | 每条告警配处理手册（`docs/runbooks/`） |
| 质量 | 第一条 eval + 回归集当发布门禁；测结果不测措辞 |

## 与骨架的关系

取：

- `telemetry` / `ai` / `core` / `session-backends` 四个共用包不变；`ai` 在业务仓里就是能力平台的 SDK。
- 垂直类的 `queue` + `dispatcher` + `<domain>/tasks`（切片）；助手类的请求内 loop + 领域 service / integrations（客服、履约管家、销售助手）；工作流类的 `graph` / `runner` / `workflows/*`（内容）。
- 「任务行才是消息」「认领必开 session」「模型可见 ⟺ 已记录」「图是数据」——全部照 `../README.md`。

原型里常见、但不进骨架的：

| 做法 | 为什么不进骨架 |
| ---- | -------------- |
| 读个人微信本地库做 ETL | 合法性与可运营性都不成立；来源应为企微存档 |
| 在云厂商语音 Demo 的场景配置里选模型 | 大脑在厂商侧；渠道不能拥有 tools / prompt |
| FFmpeg.wasm 浏览器算力 | 用户必须开着页面 |
| MCP 作为内部 RPC | 多一层连接管理，内部用 HTTP / gRPC |
| 对话记忆做成共享服务 | 对话属于产品 session；平台只存用户事实 |
| 把召回 → 画像 → RAG → Prompt → LLM → 记忆 → 抽事实写成固定流水线 | 业务配方；且「抽事实写画像」要有同意与目的限定，不能是默认行为 |
| 转人工「通过并入库」即生效 | 无版本无回归；应为草稿 → 审核 → 回归 → 发布 |

## 语言与部署口径

`../README.md` 的骨架用 TypeScript workspaces。按生态走：

- Agent 侧（loop、HTTP、tools、渠道适配）：TypeScript，包结构照骨架。
- 只有生态在 Python 的那几步才用 Python worker：企微存档 SDK 拉取、ASR、ffmpeg 渲染。脱敏 / 切分 / 预标注 / 打分留在 TS。
- 两种语言之间只有两条边界：数据库表（任务行、raw 表）和对象存储。不跨语言 import，不共享内存进度。
- 每个产品至少两个部署单元：`http`（无状态、多副本）和 `worker`（有租约、可扇出）；web 静态托管。
